# Fall Detection Waist Band

A wearable, battery-friendly fall detector built on an **ESP32** and an **MPU6050** IMU. A tiny 1D CNN, trained on the public **SisFall** dataset and quantized to full INT8, runs entirely on the microcontroller using **TensorFlow Lite Micro**. When a fall is detected, the band blinks an LED and sends an alert to a caregiver through **Telegram**.

## How it works

```
 SisFall raw logs ──► preprocess_sisfall.py ──► processed_csv/*.csv
                                                      │
                                                      ▼
                                          model1_fixed__1_.ipynb
                                     (windowing, training, INT8 export)
                                                      │
                                                      ▼
                                               model_data.h
                                                      │
                                                      ▼
 MPU6050 ──► ESP32 (FallDetection.ino) ──► 1D CNN ──► LED + Telegram alert
```

1. **Preprocess** the SisFall recordings into calibrated 50 Hz CSV files.
2. **Train** a 1D CNN in the notebook and export it as a fully quantized INT8 TFLite model, embedded in a C header together with the normalization constants.
3. **Deploy** on the ESP32: sample the IMU at 50 Hz, normalize and quantize each 2-second window, run inference every 0.5 s, and raise an alert after several consecutive positive windows.

## 1. Data preprocessing (`preprocess_sisfall.py`)

**Dataset:** [SisFall]([https://doi.org/10.3390/s17010198](https://github.com/BIng2325/SisFall/releases)), recorded at 200 Hz with an ADXL345 accelerometer and ITG3200 gyroscope worn at the waist. Files starting with `F` are falls, files starting with `D` are activities of daily living (ADL).

**What the script does**

- Reads every `.txt` file under `./SisFall_dataset/` (recursively).
- Converts raw counts to physical units:
  - Accelerometer: `raw × 32 / 8192` → g
  - Gyroscope: `raw × 4000 / 65536` → deg/s
- Downsamples by a factor of 4 (200 Hz → 50 Hz) to match the ESP32 sampling rate.
- Writes `./processed_csv/<label>.<original_name>.csv` with columns:
  `timestamp, accX, accY, accZ, gyrX, gyrY, gyrZ`

**Run it**

```bash
pip install pandas numpy
# Extract the SisFall dataset into ./SisFall_dataset first
python preprocess_sisfall.py
```

Zip the resulting `processed_csv/` folder as `processed_csv.zip` if you want to use it in Colab as the notebook does.

## 2. Model training (`model1_fixed__1_.ipynb`)

**Windowing**

- Window: 100 samples (2 s at 50 Hz) × 6 channels.
- ADL recordings: sliding windows with a 25-sample (0.5 s) hop.
- Fall recordings: only windows that contain the impact peak (with at least 30 samples of context on each side) are labelled "fall", shifted in 5-sample steps for augmentation. The standing-before and lying-after portions are dropped because they are ambiguous.

**Splitting and normalization**

- 70 / 15 / 15 split **by subject** (separately for young `SA` and elderly `SE` groups), so no person appears in more than one split. This gives 26 / 5 / 7 train / val / test subjects.
- Per-channel z-score; statistics are computed on the training set only.
- Dataset size after windowing: 112,468 windows (16,182 fall, 96,286 ADL). Class weights compensate for the imbalance.

**Architecture (1D CNN)**

```
Input (100, 6)
Conv1D(16, k=5, stride=2) → BN → ReLU → MaxPool(2)
Conv1D(32, k=5)           → BN → ReLU → MaxPool(2)
Conv1D(32, k=3)           → BN → ReLU
GlobalAveragePooling1D → Dropout(0.3) → Dense(16, ReLU) → Dense(1, sigmoid)
```

Training uses Adam (lr 1e-3), batch size 128, up to 80 epochs, early stopping, and learning-rate reduction on plateau.

**Quantization:** post-training full-integer INT8 quantization with 500 representative samples from the training set (int8 input and output).

**Results (held-out test subjects, INT8 model, threshold 0.5)**

| Metric | Value |
|--------|-------|
| Recall (fall sensitivity) | 99.46 % |
| Specificity | 99.57 % |

**Outputs written by the notebook:** `norm_stats.npz`, `fall_cnn.keras`, `fall_cnn_int8.tflite`, and `model_data.h`.

**Run it**

1. Open the notebook in Google Colab.
2. Upload `processed_csv.zip` and run all cells (the first cell unzips it).
3. Download the generated `model_data.h` and place it next to the `.ino` file.

## 3. Firmware (`FallDetection.ino`)

### Hardware

| Part | Notes |
|------|-------|
| ESP32 dev board | Dual core; Telegram runs on core 0 so sampling is never blocked |
| MPU6050 IMU | I²C address `0x68`, configured for ±16 g and ±2000 deg/s to match SisFall ranges |
| LED + 220 Ω resistor | Alert indicator |
| Push button | Acknowledge alert (wired to GND, uses `INPUT_PULLUP`) |
| Waist-band enclosure + battery | Mount the IMU firmly at the waist |

### Pin map

| Signal | ESP32 pin |
|--------|-----------|
| MPU6050 SDA | GPIO 21 |
| MPU6050 SCL | GPIO 22 |
| Alert LED | GPIO 26 |
| Acknowledge button | GPIO 27 |

### Software requirements

- Arduino IDE (or PlatformIO) with the **ESP32 board package**
- Library: **Chirale_TensorFlowLite** (Arduino Library Manager)
- `model_data.h` in the same folder as `FallDetection.ino`

### Configuration

Set the following constants at the top of `FallDetection.ino`:

```cpp
const char* WIFI_SSID = "<your WiFi name>";
const char* WIFI_PASS = "<your WiFi password>";
const char* BOT_TOKEN = "<Telegram bot token from @BotFather>";
const char* CHAT_ID   = "<Telegram chat ID of the caregiver>";
```

Tunable parameters:

| Constant | Default | Meaning |
|----------|---------|---------|
| `FALL_THRESHOLD` | `0.85` | Minimum P(fall) for a window to count as positive |
| `CONSEC_REQUIRED` | `3` | Consecutive positive windows needed to confirm a fall (lower = faster but more false alarms) |
| `INFER_STRIDE` | `25` | Run inference every 25 samples (0.5 s) |
| `PRINT_SAMPLE_EVERY` | `10` | Print a debug sample every N samples (0 disables) |

### Runtime behaviour

1. **Sampling:** the MPU6050 is read at 50 Hz, and axes are remapped to the SisFall coordinate frame (`ax' = ay`, `ay' = -ax`, `gx' = gy`, `gy' = -gx`) so live data matches the training data.
2. **Windowing:** samples fill a 100-sample circular buffer.
3. **Inference:** every 0.5 s the window is z-score normalized, quantized to INT8, and passed to the CNN. The output is dequantized into P(fall).
4. **Confirmation:** an alert is raised only after `CONSEC_REQUIRED` consecutive windows reach `FALL_THRESHOLD`.
5. **Alert state:** the LED blinks and a Telegram message ("FALL DETECTED! Confidence …") is queued and sent from a background task, with up to 5 retries.
6. **Acknowledge:** pressing the button returns the band to monitoring, clears the window, and sends an "acknowledged" message.

The serial monitor (115200 baud) prints the model input shape, arena usage, per-inference probability and latency, and state changes.

### Upload steps

1. Install the ESP32 board package and the Chirale_TensorFlowLite library.
2. Wire the hardware according to the pin map.
3. Put `FallDetection.ino` and `model_data.h` in one sketch folder.
4. Fill in the Wi-Fi and Telegram settings.
5. Select your ESP32 board, upload, and open the Serial Monitor at 115200 baud.

## Security note

Never commit real Wi-Fi passwords or Telegram bot tokens to a shared repository. If a token has already been pushed or shared, **revoke it in @BotFather (`/revoke`) and generate a new one**. Consider moving secrets into a separate, git-ignored `secrets.h` file.

The firmware also uses `client.setInsecure()` for HTTPS, which skips certificate validation. This is fine for a prototype but should be replaced with proper certificate pinning for real use.

## Limitations

- Trained on SisFall only (lab-simulated falls); real-world performance may differ, especially for wearers whose motion patterns differ from the dataset's volunteers.
- Sensor placement and orientation must match the axis remapping in the firmware.
- Alerts need Wi-Fi; if the network is down the message is retried but may be delayed.
- This is a student prototype and **not a certified medical device**.
